**Design Decision:** One deliberate choice was isolating all sensitive configuration — the Gateway URL, Knowledge Base ID, region, and Memory ID — into a `.env` file rather than hardcoding them into `main.py`. This keeps secrets out of version control (paired with a `.gitignore` entry) and separates configuration from logic, so the same codebase can point at different resources (dev vs. staging vs. production Memory/Gateway instances) just by swapping environment values, without touching a single line of code.

**Challenge:** The most persistent issue was a `ParamValidationError: Invalid type for parameter memoryId, value: None` that only appeared after deployment, despite the agent working correctly in local testing. Locally, `load_dotenv()` successfully read `.env` and populated `MEMORY_ID`, `GATEWAY_URL`, and related variables. But `agentcore deploy` packages and ships the Python code to AWS without including the local `.env` file, so on the deployed runtime, every `os.getenv()` call silently returned `None` instead of erroring — which meant the failure surfaced deep inside a boto3 parameter-validation check rather than at the point of misconfiguration. Diagnosing it required comparing local vs. deployed behavior directly, tracing the error back to environment-variable resolution rather than agent logic, and discovering that `agentcore deploy` supports a `--env KEY=VALUE` flag to inject variables directly into the deployed container's environment. The fix didn't require any code changes — the existing `os.getenv()` calls worked identically whether values came from a loaded `.env` file locally or from injected environment variables in the cloud.

**Production Extension:** For a production deployment, I would introduce structured output — constraining the agent's responses to a validated schema like using Pydantic models rather than free-form text. This would make the inclusion of the Agent in a pipleine more reliable and consistent. For example, order-tracking responses, refund confirmations, and loyalty-discount calculations could be parsed deterministically by other services instead of relying on string parsing or prompt-engineered formatting. This would reduce silent failures and making the agent easier to integrate into a broader customer-support pipeline.
